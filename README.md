## 💡 О проекте и решаемая задача

Стандартный рабочий процесс разработчика или DevOps-инженера с Docker часто выглядит так:
```bash
docker ps -a
docker logs -f my-container-name
docker stop my-container-name
docker rm my-container-name
```

Постоянное переключение контекста, запоминание длинных идентификаторов и ввод громоздких CLI-команд замедляют работу. С другой стороны, графические клиенты вроде Docker Desktop потребляют сотни мегабайт оперативной памяти и тяжеловесны для удаленных серверов.

**DockDash решает эту проблему:**
1. **Легковесность:** Скомпилированный бинарник занимает менее 11 МБ и потребляет всего 15–20 МБ RAM.
2. **Нулевой фриз интерфейса:** Все сетевые и файловые вызовы к Docker API изолированы в отдельных горутинах и общаются с UI через асинхронную шину сообщений Bubble Tea.
3. **Универсальность:** Работает везде — локально в Windows Terminal / macOS iTerm / Linux Bash, а также через SSH на удаленных серверах.
4. **Работает без Docker (Demo Mode):** Если локальный демон выключен или недоступен, программа мгновенно запускает живой симулятор микросервисов (API Gateway, Redis, PostgreSQL, Worker, Nginx), позволяя протестировать весь функционал без предварительной настройки.

## 🚀 Что нового в версии 2.0.0 (Global Update)

В версии **2.0.0** DockDash получил масштабное обновление архитектуры и 6 ключевых enterprise-инструментов:

1. 💻 **Interactive Shell Exec (`x` / `e`):** мгновенный вход в терминал контейнера (`bash`/`sh`) с прямым захватом TTY и бесшовным возвратом в TUI.
2. 📦 **Docker Compose Stacks (`g` / `Tab`):** группировка контейнеров в стеки проектов, сворачивание и одновременный старт/стоп/рестарт целого стека в 1 клик.
3. 🔍 **Professional Log Engine (`/`, `n`/`N`, `e`, `Shift+S`):** Vim-поиск по регулярным выражениям Regex с подсветкой, изоляция ошибок (`ERROR`/`FATAL`/`5xx`) и временной срез `--since` (All, 15m, 1h, 24h).
4. ⚡ **cgroups Throttling & OOM Alerting:** автоматическое выявление удушения процессора CFS CPU Throttling (`⚠️`), предупреждение риска OOM (>90% RAM) и статус `💀 OOM KILLED` (код 137).
5. 🗄️ **Images & Disk Auditor (`p`):** визуальный анализ слоев Docker-образов (dive-style) с подсветкой раздутых слоев (>50 MB) и безопасная целевая очистка (Targeted Prune).
6. 🌐 **Multi-Host Contexts Switcher (`c`):** переключение на удаленные серверы Docker (`ssh://`, staging, production) прямо из интерфейса на лету.

> 📖 *Полный базовый функционал, быстрый старт и таблица горячих клавиш описаны ниже.*

## ✨ Возможности

- ⚡ **Управление жизненным циклом в одно нажатие:**
  - `Space` — старт и остановка контейнера (или всего Docker Compose стека)
  - `x` / `e` — **интерактивный шелл** (`bash`/`sh`) в контейнере с прямым захватом TTY и возвратом в дашборд
  - `r` — перезапуск контейнера или всего стека
  - `Shift+K` — принудительное завершение аварийного процесса (`SIGKILL`)
  - `d` — безопасное удаление контейнера через диалоговое окно
- 📦 **Группировка по Docker Compose стекам (`g` / `Tab`):**
  - Древовидная иерархия контейнеров по проектам и сервисам Compose
  - Сворачивание и разворачивание проектов клавишей `Tab`
  - Массовые операции: одновременный запуск, остановка и перезапуск целого стека
- 📊 **Мониторинг нагрузки и метрики cgroups:**
  - Живые графические индикаторы CPU и RAM (`[■■■■□□□□]`)
  - **Детектирование CFS CPU Throttling (`⚠️`):** предупреждение, если контейнеру не хватает процессорной квоты cgroups
  - **OOM Risk Warning:** предупреждение при превышении 90% лимита оперативной памяти
  - **Детектирование OOM Killed:** отображение статуса `💀 OOM KILLED` при аварийном завершении по коду 137
- 📜 **Профессиональный движок логов (Log Engine):**
  - Полноэкранный просмотр скроллируемых логов с автоскроллом (`Follow Mode`)
  - **Vim Regex Search (`/`):** быстрый поиск по регулярным выражениям с подсветкой совпадений и навигацией `n` / `N`
  - **Изоляция ошибок (`e`):** мгновенный фильтр только строк с ошибками (`ERROR`, `FATAL`, `PANIC`, `5xx`)
  - **Фильтрация времени `--since` (`Shift+S`):** просмотр свежих логов за последние 15 минут, 1 час или 24 часа
- 🗄️ **Аудитор диска и анализ слоев Dive-style (`p`):**
  - Детальный расклад занятого диска: Образы, Контейнеры, Тома (Volumes), Build Cache
  - **Анализ слоев образов:** отображение каждой инструкции Dockerfile с подсветкой раздутых слоев (> 50 MB)
  - **Целевая безопасная очистка (Targeted Prune):** раздельная очистка неиспользуемых образов (`1`), остановленных контейнеров (`2`), томов (`3`), кэша сборщика (`4`) или всего освобождаемого места (`a`)
- 🌐 **Мульти-хост переключатель контекстов (`c`):**
  - Подключение к локальным и удаленным Docker-демонам (`ssh://`, staging, prod) прямо из интерфейса на лету
- 🔍 **Мгновенный поиск и фильтрация (`/`):**
  - Поиск по имени контейнера, Docker-образу, проекту Compose и ID
- 🔀 **5 режимов сортировки (`s`):**
  - По умолчанию, по имени (A-Z), по статусу (Running первыми), по нагрузке CPU%, по использованию RAM
- 🔬 **Инспектор конфигурации (`i`):**
  - IP-адреса, порты, сетевые интерфейсы, точки монтирования (Volumes), переменные окружения (Env) и параметры cgroups
- 🌐 **Полная поддержка русской раскладки:**
  - Все горячие клавиши дублированы для русской раскладки клавиатуры (`й`, `ы`, `к`, `л`, `ш`, `е`, `з`, `п`, `ч`, `у`)

## 📥 Установка и быстрый старт

### 1. Запуск без установки (Demo-режим)
Если вы хотите просто посмотреть приложение в действии (даже если Docker сейчас выключен):
```bash
go run ./cmd/dockdash --demo
```
*(Или просто запустите `go run ./cmd/dockdash` — приложение автоматически определит состояние демона и включит демо-режим, если Docker не запущен).*

### 2. Запуск с реальным Docker
1. Убедитесь, что Docker Desktop или сервис Docker запущен.
2. *(Опционально)* Поднимите готовый тестовый кластер из репозитория:
   ```bash
   docker compose -f docker-compose.test.yml up -d
   ```
3. Запустите дашборд:
   ```bash
   go run ./cmd/dockdash
   ```

### 3. Сборка самостоятельного файла (.exe / binary)
Соберите оптимизированный исполняемый файл без отладочных символов:

**Windows (PowerShell):**
```powershell
go build -ldflags="-s -w" -o dockdash.exe ./cmd/dockdash
.\dockdash.exe
```

**Linux / macOS (Bash):**
```bash
go build -ldflags="-s -w" -o dockdash ./cmd/dockdash
./dockdash
```

## 🕹 Горячие клавиши (Keybindings)

### Главный экран (Список контейнеров)

| Англ. | Рус. | Действие |
| :---: | :---: | :--- |
| `↑` / `↓` | `↑` / `↓` | Перемещение по списку контейнеров |
| `k` / `j` | `л` / `о` | Vim-навигация вверх / вниз |
| `Tab` / `Enter` | `Tab` / `Enter` | **Свернуть / развернуть стек** Docker Compose |
| `g` | `п` | **Группировка** (Переключение между Compose-стеками и плоским списком) |
| `Space` | `Пробел` | **Старт / Остановка** выбранного контейнера (или всего стека) |
| `x` / `e` | `ч` / `у` | **Интерактивный шелл** (`sh` / `bash`) внутри контейнера |
| `r` | `к` | **Перезапуск** контейнера или всего стека (Restart) |
| `p` | `з` | **Аудитор диска и слоев образов (Dive-style & Prune)** |
| `c` | `с` | **Выбор Docker Context (Multi-Host Switcher)** |
| `Shift+K`| `Shift+Л`| **Принудительное завершение** (`SIGKILL`) с подтверждением |
| `d` | `в` | **Удалить контейнер** (открывает окно подтверждения) |
| `Enter` / `l` | `Enter` / `д` | Открыть **живые логи** контейнера |
| `i` | `ш` | **Инспектор конфигурации** (IP, порты, диски, env) |
| `s` | `ы` | **Сортировка** списка (Имя → Статус → CPU → RAM) |
| `/` | `/` | **Поиск / Фильтрация** по названию, образу или проекту |
| `q` / `Ctrl+C` | `й` | **Выход** из программы |

### Экран логов (Logs View)

| Клавиша | Действие |
| :---: | :--- |
| `/` / `ю` | **Поиск по логам** (поддержка текста и регулярных выражений **Regex**) |
| `n` / `т` | Переход к **следующему совпадению** поиска |
| `N` / `Т` | Переход к **предыдущему совпадению** поиска |
| `e` / `у` | **Изоляция ошибок (Error Isolation)**: показать только ERROR/FATAL/WARN/5xx |
| `Shift+S` / `Shift+Ы` | **Фильтр по времени (`--since`)**: All → 15m → 1h → 24h |
| `f` / `а` | Переключить режим автоскролла (**Follow Mode** ON/OFF) |
| `t` / `е` | Показать / скрыть метки времени (**Timestamps**) |
| `c` / `с` | Очистить экран логов |
| `↑` / `↓` | Построчная прокрутка логов вверх / вниз |
| `PgUp` / `PgDn` | Быстрая постраничная прокрутка |
| `Esc` / `Backspace` | Сброс поиска / Вернуться назад к списку контейнеров |

### Экран инспектора (Inspect View)

| Клавиша | Действие |
| :---: | :--- |
| `↑` / `↓` | Прокрутка параметров конфигурации |
| `k` / `j` | Быстрое переключение инспекции на предыдущий / следующий контейнер |
| `Esc` / `Backspace` | Вернуться назад к списку контейнеров |

### Экран аудита диска и образов (Disk & Layers View)

| Клавиша | Действие |
| :---: | :--- |
| `↑` / `↓` | Выбор образа из списка |
| `Enter` | **Анализ слоев выбранного образа (dive-style)** с подсветкой раздутых слоев |
| `1` | **Prune Images**: безопасная очистка неиспользуемых образов |
| `2` | **Prune Containers**: удаление всех остановленных контейнеров |
| `3` | **Prune Volumes**: очистка неиспользуемых томов (Dangling Volumes) |
| `4` | **Prune BuildCache**: очистка кэша сборщика BuildKit |
| `a` / `ф` | **Prune All**: полная очистка всего освобождаемого места |
| `Esc` / `Backspace` | Закрыть просмотр слоев / Вернуться назад к списку контейнеров |
